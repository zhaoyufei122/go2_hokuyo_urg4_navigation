# GO2 RTAB-Map 3D Mapping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox syntax for tracking.

**Goal:** Add a motion-free GO2 3D mapping launch that removes robot self
returns, builds a loop-closed RTAB-Map database from the deskewed L2 cloud, and
shows the result interactively.

**Architecture:** Reuse the existing planar_odom adapter only for its
odom-to-base TF chain. Transform the deskewed cloud into base_link, remove the
GO2 body with a negative PCL CropBox, downsample to 8 cm, then feed the cloud to
RTAB-Map. RTAB-Map reads odometry from odom-to-base_link TF, not the planar
/odom message, and writes a configurable database.

**Tech Stack:** ROS 2 Jazzy, Unitree ROS 2, pcl_ros components, RTAB-Map ROS 2,
Python launch, YAML, pytest, colcon.

## Global Constraints

- Do not start Nav2, the Unitree command bridge, teleoperation, or any node that
  can publish /cmd_vel or /api/sport/request.
- Do not add load to the GO2 onboard computer; all new processing runs on the
  desktop.
- Keep the full 360-degree environment cloud. Remove only the robot body
  volume and near-range returns; retain floor, chair legs, and table geometry.
- Use /utlidar/cloud_deskewed directly. Do not deskew a second time.
- The offline implementation and verification must not require the robot to be
  powered on.
- Work in the current branch because the operator explicitly requested direct
  execution in this workspace.
